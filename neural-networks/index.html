Day 1 | Intuition

The basic intuition. Weighted signal flow

A neural network passes input values through layers of weighted combinations. Each layer transforms the representation so the network can learn patterns that are harder to describe manually.

Day 1 | Building block

What is a neuron?

Inputs

Feature values or outputs from the previous layer.

Output

A transformed score after weights, bias, and activation are applied.

One neuron is simple. Many neurons stacked in layers allow richer pattern learning.

Day 1 | Architecture

Input layer, hidden layers, output layer

LayerRole
InputReceives raw features such as balances, counts, or encoded categories.
HiddenLearns intermediate representations that capture structure.
OutputProduces the final prediction such as class probability or numeric value.
Day 1 | Flow

Forward pass. What happens in prediction mode

  1. Inputs enter the first layer.
  2. Weights and bias combine signals.
  3. An activation function transforms the result.
  4. The process repeats through deeper layers.
  5. The final layer produces an output score or value.
Day 1 | Math idea

Weights and bias in plain language

Weights decide how strongly each input matters. Bias shifts the decision boundary. Together, they allow the model to respond differently across patterns in the data.

Practical view

Training is largely the process of improving these values so the network performs better on the target task.

Day 1 | Why depth matters

Why hidden layers are useful

Multiple layers allow the network to learn representations step by step. Early layers may learn simple patterns. Later layers combine them into more meaningful abstractions.

Day 1 | Non-linearity

Why activation functions matter

Without activation functions, stacked layers collapse into a linear transformation. Activations create non-linearity, which is what allows the network to learn richer patterns.

Day 1 | Activation

ReLU. The workhorse activation

Definition

Returns the input if it is positive, otherwise zero.

Why popular

Simple, efficient, and often easier to optimise in deep networks.

Day 1 | Activation

Sigmoid and tanh. Where they fit

  • Sigmoid maps values to 0 to 1, useful for binary output interpretation.
  • Tanh maps values to -1 to 1, sometimes useful in hidden layers in older architectures.
  • Both can saturate, which can make training slower or less stable.
Day 1 | Output design

Choosing output activations

TaskTypical output
Binary classificationSigmoid
Multi-class classificationSoftmax
RegressionLinear output
Day 1 | Loss

What a loss function does

The loss function measures how wrong the model is. Training aims to reduce loss by adjusting weights and bias in a direction that improves predictions.

Day 1 | Loss

Common loss functions

Binary cross-entropy

Common for binary classification.

Categorical cross-entropy

Common for multi-class classification.

Mean squared error

Common for regression tasks.

Day 1 | Learning

What training really means

Training is repeated adjustment. The model predicts, compares its output to the true answer, calculates loss, and updates parameters to reduce future error.

Day 1 | Backpropagation

Backpropagation in plain English

Backpropagation tells each parameter how much it contributed to the error. It sends the learning signal backwards from output to earlier layers so the network can update intelligently.

Day 1 | Optimisation

Gradient descent intuition

Gradient descent is a search process. It follows the slope of the loss surface to move parameters toward lower error.

Practical meaning

If the step is too large, training can overshoot. If it is too small, training may crawl or stall.

Day 1 | Hyperparameters

What is a learning rate?

The learning rate controls the size of each update step during optimisation. It is one of the most important choices in neural network training.

Day 1 | Hyperparameters

Batch size and epochs

Batch size

How many examples are processed before an update.

Epoch

One full pass through the training dataset.

Effect

These choices affect speed, stability, and generalisation.

Day 1 | Pipeline

Typical training loop

for epoch in range(num_epochs):
    for batch_x, batch_y in loader:
        pred = model(batch_x)
        loss = loss_fn(pred, batch_y)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
Day 1 | Interpretation

Reading learning curves

Training and validation loss curves help you see whether the model is learning, stalling, or starting to overfit. These curves are often more informative than a single final score.

Day 1 | Overfitting

How overfitting appears in neural training

Symptom

Training loss keeps improving while validation loss stalls or worsens.

Meaning

The network is memorising details of the training data rather than generalising.

Day 1 | Control

Regularisation strategies

  • Dropout
  • Weight decay
  • Early stopping
  • More data or augmentation
  • Simpler architecture
Day 1 | Dropout

What dropout is doing

Dropout randomly disables some neurons during training. This discourages fragile co-dependence and can improve generalisation.

Day 1 | Stability

Normalisation and stable training

Careful scaling and batch normalisation can help training behave more smoothly. Stability matters because unstable training can waste time and hide architecture problems.

Day 1 | Data prep

Preparing structured banking data for neural networks

  1. Clean missing values and invalid records.
  2. Encode categorical features carefully.
  3. Scale numeric features when needed.
  4. Create train, validation, and test splits with leakage control.
Day 1 | Features

Dense features and sparse features

Dense

Sparse

High-dimensional encoded inputs such as rare categories or text token indicators.

Day 1 | Architecture choice

How to choose an architecture sensibly

Start with the simplest architecture that fits the task. Architecture choice should reflect data type, objective, available compute, and governance constraints.

Day 1 | Failure modes

Common training failure modes

No learning

Loss barely moves because setup is wrong.

Unstable learning

Loss jumps wildly due to poor optimisation settings.

Memorisation

Training improves while validation degrades.

Day 1 | Compute reality

Why compute and data volume matter

Neural networks are often expensive to train compared with simpler models. Before choosing them, ask whether the performance gain justifies the operational cost and complexity.

Day 2 | CNN intuition

Why convolutional neural networks were created

Standard dense networks do not naturally exploit local spatial structure in images. CNNs were designed to detect meaningful local patterns such as edges, shapes, and regions more efficiently.

Day 2 | CNN intuition

What convolution is doing

A small filter moves across the input and produces feature maps that highlight useful local patterns. This is powerful for images, scanned forms, signatures, and other document artifacts.

Day 2 | CNN parts

Core CNN building blocks

Convolution

Detects local patterns using filters.

Activation

Adds non-linearity to the detected signals.

Pooling

Compresses and summarises features.

Day 2 | Feature maps

How feature maps evolve through layers

Early layers detect simple structures. Deeper layers combine them into more meaningful patterns such as shapes, layout regions, or visual signatures.

Day 2 | Banking use case

CNNs in banking document understanding

Possible tasks

Document classification, signature checks, scanned form routing, and image quality triage.

Need for care

Visual quality, sensitive information, and misclassification consequences can be significant.

Day 2 | Pooling

Why pooling helps

Pooling reduces spatial dimensions while retaining the most useful signals. This lowers compute needs and can improve robustness to small shifts in the input.

Day 2 | Transfer learning

What transfer learning is

Transfer learning starts from a model already trained on a large dataset, then adapts it to your task. This is often far more practical than training from scratch.

Day 2 | Why it matters

Why transfer learning is so useful in practice

  • Needs less data than training from scratch
  • Usually trains faster
  • Often performs better in constrained settings
  • Can be more realistic for enterprise teams
Day 2 | Fine-tuning

Feature extraction versus fine-tuning

Feature extraction

Freeze most layers and train only the final head.

Fine-tuning

Unfreeze more layers and adapt deeper representations to your domain.

Day 2 | Data quality

Data preparation for image and document tasks

  1. Check resolution and orientation consistency.
  2. Label carefully and review edge cases.
  3. Separate train, validation, and test with leakage awareness.
  4. Protect sensitive information in storage and handling.
Day 2 | Augmentation

What data augmentation is doing

Augmentation creates realistic variation such as rotation, crop, or noise to help the model generalise. It must reflect plausible real conditions, not fantasy inputs.

Day 2 | Monitoring

Monitoring neural systems after deployment

Input drift

Changes in image or document quality.

Prediction drift

Changes in score or class distribution.

Outcome drift

Changes in true result rates and operational feedback.

Day 2 | Explainability

Why explainability is harder here

Deep models often achieve strong performance at the cost of transparency. Explainability tools help, but they do not remove the need for human judgement and challenge.

Day 2 | Risk

Banking risk questions for neural applications

  3. What fallback exists if the model fails?
  4. How will drift or degraded image quality be detected?
  5. What evidence supports fairness and robustness?
Day 2 | Tuning

Hyperparameter tuning without chaos

Tuning should be systematic. Change one family of choices at a time, log results carefully, and compare on the same validation regime.

Day 2 | Tuning

Manual search, grid search, and practical tuning
